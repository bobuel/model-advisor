# Research that informs recommendations

The user journey is: describe a coding task and priorities in the plugin, supply current harness options, and receive a supported model/effort recommendation with research citations and honest measurement limits. Research maintains the evidence; Liquid chooses from that evidence. Liquid d1 is not the open-ended researcher.

The reviewed report is embedded in `knowledge/current.json`. Version 2026-10-21.1 contains seven findings checked against current official guidance on October 21, 2026; Max and Ultra now have separate model scopes. The initial six-finding report was reviewed on October 10. They cover Sol 6.1, Astra, Luna and effort tradeoffs. The document hash, retrieval time, section references, limitations and review hash travel with the report. This is provider guidance, not independent benchmark proof. Older-model fit, dollar costs and harness speed controls still need research. The original 18 synthetic observations keep their original dates and scope.

## LangChain implementation and provenance

`research-agent.mjs` uses the OSS JavaScript `createDeepAgent` implementation, pinned to deepagents 1.14.2. Its workflow adapts the planning, URL discovery, full-page reading and synthesis approach in [LangChain's deep_research example](https://github.com/langchain-ai/deepagents/tree/9f0e39d55a5f31003b206b31b955154f2f1bc49a/examples/deep_research). The [JavaScript repository](https://github.com/langchain-ai/deepagentsjs/tree/b448f220866bbb5d41924dfdbb1e0079c3b11838) supplies the runtime. This is an adaptation, not a claim that LangChain provides our model recommendations.

The exported `runResearch({model, search, question})` accepts an explicitly configured LangChain chat-model object and a search adapter returning `{url,title}` entries. Both must honor abort signals and have their own provider retry/output-token limits. The agent has no default provider. We have not selected or enabled a paid research model or search account. The real LangChain graph is tested with a scripted model and controlled HTTP results; a live LangChain research run has not been observed.

A separately configured Codex heartbeat is the intended research route under the current $0 hosting decision; its current enablement and unattended operation were not verified in the October 21 review. It can use its existing web tools to prepare the same report and perform the separate maintainer review. The first report was researched this way, not generated by the offline LangChain test. No new worker, database, queue or hosted service was added.

## Bounds and publication

One invocation permits at most 12 model turns, five searches, eight source reads and two minutes. Reads allow only explicit primary domains, deny redirects, and cap each document at 200 KB. Search only discovers URLs. A citation must point to a fetched source. No search snippets count as evidence. The agent cannot fetch private hosts, execute shell commands, edit the repository, delegate or publish. Built-in filesystem, subagent and summarization middleware are replaced; the tool allowlist also enforces the boundary at execution.

The agent outputs a draft. A maintainer separately checks each claim against the named section, checks disagreements and billing context, records remaining gaps, and binds a review to the exact draft hash. Validation checks shape, provenance references, source ledger, dates, scope and review hash; it cannot prove that a sentence follows from a source. The review field is an audit record protected by repository review, not a cryptographic identity signature. Never manufacture it inside the research agent.

The production payload carries the reviewed findings and sources. All supported catalog configurations remain visible, but catalog membership alone cannot justify a returned recommendation. A selected configuration needs model-fit research or matching measured observations. No exact-target test is required. Model-specific effort findings take precedence over generic editorial preferences. Report expiry cannot be extended by a successful fetch alone.

For a release, review changed facts and opinions, add affected request cases, run the normal repository checks, and publish the scoped update. Price changes require billing-specific cases; new capability claims require matching harness and real-task evidence before they can be called measured. Hosted deployment remains blocked by the user's $0 budget.

## Verification and dependency limitation

`tests/research.test.mjs` executes the actual LangChain graph offline and checks discovery/read/citation flow, rejected fabricated citations, forbidden tools, budgets, repeated runs and unapproved/altered/stale reports. Production HTTP and MCP tests consume the same updated knowledge package. Scripted decisions test wiring, not whether Liquid's new ranking is good; a new live routing evaluation remains outstanding and must fit the remaining authorized allowance.

The installed research-only dependency tree reports the braces nested-pattern stack-exhaustion advisory [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm), inherited through fast-glob. We did not apply npm's suggested incompatible downgrade. Filesystem/glob/grep tools are removed and forbidden in this agent, and dev dependencies are omitted from the production image. Reassess before enabling any filesystem research tools or a live research provider.
